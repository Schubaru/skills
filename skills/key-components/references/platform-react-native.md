# Platform: React Native (TypeScript) — the default

Target: iOS first, Android compatible. Expo or bare RN both fine; detect from `package.json` and don't introduce Expo-only APIs into a bare project.

## Files produced

```
design-system/
├── tokens/tokens.ts             # generated by build_tokens.py
├── theme/
│   ├── ThemeProvider.tsx        # context + useTheme() + useColorScheme bridge
│   └── index.ts
├── components/
│   ├── Button.tsx … (inventory order)
│   ├── Button.stories.tsx … (one per component, see references/storybook.md)
│   ├── index.ts                 # barrel export
│   └── manifest.json
└── previews/
    └── Gallery.tsx              # a scrollable screen rendering every component/variant/state
.rnstorybook/                    # on-device Storybook config (main.ts, preview.tsx); see references/storybook.md
```

Check the repo for an existing `src/` or `app/` convention. If the project keeps UI under `src/`, place `design-system/` at root anyway (the user's fixed location) and add a path alias `@ds/*` in `tsconfig.json` / `babel.config.js` (module-resolver) so imports read `import { Button } from '@ds/components'`.

## ThemeProvider template

```tsx
import React, { createContext, useContext, useMemo } from 'react';
import { useColorScheme } from 'react-native';
import { tokens, type Theme, type Mode } from '../tokens/tokens';

const ThemeContext = createContext<Theme>(tokens.light);

export function ThemeProvider({ mode, children }: { mode?: Mode; children: React.ReactNode }) {
  const system = useColorScheme();
  const resolved: Mode = mode ?? (system === 'dark' ? 'dark' : 'light');
  const theme = useMemo(() => tokens[resolved], [resolved]);
  return <ThemeContext.Provider value={theme}>{children}</ThemeContext.Provider>;
}

export const useTheme = () => useContext(ThemeContext);
```

`tokens.light` / `tokens.dark` are the resolved semantic trees; `tokens.primitive` is available but components should not reach for it.

## Component file template

Every component follows this exact shape so files are interchangeable to read:

```tsx
/**
 * Button
 * Category: actions
 * Purpose: Primary way to trigger an action.
 * Use for: submitting, confirming, starting a flow.
 * Don't use for: navigation (Link), toggling state (Chip/Switch).
 * Anatomy: container · label · leadingIcon? · trailingIcon? · loading
 */
import React from 'react';
import { Pressable, Text, View, ActivityIndicator, type PressableProps } from 'react-native';
import { useTheme } from '../theme';

export type ButtonVariant = 'primary' | 'secondary' | 'tertiary' | 'danger';
export type ButtonSize = 'sm' | 'md' | 'lg';

export interface ButtonProps extends Omit<PressableProps, 'style' | 'children'> {
  label: string;
  variant?: ButtonVariant;
  size?: ButtonSize;
  leadingIcon?: React.ReactNode;
  trailingIcon?: React.ReactNode;
  loading?: boolean;
  fullWidth?: boolean;
}

const SIZE = { sm: { h: 32, px: 3, role: 'sm' }, md: { h: 44, px: 4, role: 'md' }, lg: { h: 52, px: 5, role: 'lg' } } as const;

export function Button({ label, variant = 'primary', size = 'md', leadingIcon, trailingIcon, loading, fullWidth, disabled, ...rest }: ButtonProps) {
  const t = useTheme();
  const s = SIZE[size];
  const font = t.font.label[s.role];
  const palette = {
    primary:   { bg: t.bg.accent.default, bgPressed: t.bg.accent.pressed, fg: t.text.onAccent, border: 'transparent' },
    secondary: { bg: t.surface.default,   bgPressed: t.bg.muted,          fg: t.text.default,  border: t.border.strong },
    tertiary:  { bg: 'transparent',       bgPressed: t.bg.accent.subtle,  fg: t.text.accent,   border: 'transparent' },
    danger:    { bg: t.bg.danger.strong,  bgPressed: t.bg.danger.pressed, fg: t.text.inverse,  border: 'transparent' },
  }[variant];
  const isDisabled = disabled || loading;

  return (
    <Pressable
      accessibilityRole="button"
      accessibilityState={{ disabled: !!isDisabled, busy: !!loading }}
      disabled={isDisabled}
      hitSlop={size === 'sm' ? 6 : 0}
      style={({ pressed }) => ({
        height: s.h,
        paddingHorizontal: t.space[s.px],
        borderRadius: t.radius.md,
        borderWidth: palette.border === 'transparent' ? 0 : t.border.width.regular,
        borderColor: palette.border,
        backgroundColor: pressed ? palette.bgPressed : palette.bg,
        opacity: isDisabled ? t.opacity.disabled : 1,
        flexDirection: 'row', alignItems: 'center', justifyContent: 'center', gap: t.space[2],
        alignSelf: fullWidth ? 'stretch' : 'flex-start',
      })}
      {...rest}
    >
      {loading ? <ActivityIndicator color={palette.fg} /> : (
        <>
          {leadingIcon}
          <Text style={{ color: palette.fg, fontFamily: font.family, fontSize: font.size, lineHeight: font.lineHeight, fontWeight: font.weight, letterSpacing: font.letterSpacing }}>{label}</Text>
          {trailingIcon}
        </>
      )}
    </Pressable>
  );
}
```

Conventions the template encodes, apply them everywhere:

- Named export, no default export. Barrel in `components/index.ts`.
- Size tables are local constants keyed to `space` steps and font role sizes, never raw numbers for padding.
- `Pressable` with a style function for pressed state; never `TouchableOpacity` (it overrides opacity semantics used for disabled).
- Accessibility role and state always set.
- Icons are passed in as `ReactNode`; the design system doesn't pick an icon library. If the project has one, the Gallery uses it; otherwise Gallery uses simple `Text` glyphs.
- Fonts: if `font.family.*` names a custom font, note in the doc that the project must load it (Expo `useFonts` or `react-native.config.js` assets). Emit weight-specific family names if the font ships static weights (`Inter-SemiBold`), since RN on Android ignores `fontWeight` for custom fonts. The token script emits `font.family.<role>.<weight>` variants when `type.staticWeights: true` in the spec.
- Shadows: use `t.elevation[n]` which contains `shadowColor/shadowOffset/shadowOpacity/shadowRadius` and `elevation` together; spread it.
- Focus: RN has no focus ring by default. Expose `focusable` and apply `border.focus` when `focused` via `onFocus/onBlur` for TV/keyboard; note that in the doc rather than faking it.

## Storybook (primary workbench)

On-device Storybook via `@storybook/react-native`, stories generated from the manifest then hand-extended. Setup, story conventions, and the generator are in `references/storybook.md`. The Gallery below stays because it needs no Storybook install and runs inside the app itself; both consume the same components.

## Gallery (native preview)

`previews/Gallery.tsx` is a `ScrollView` with a section per component in inventory order, rendering every variant × size × relevant state, plus a mode toggle at the top that re-mounts `ThemeProvider` with `mode="light" | "dark"`. Register it however the project runs screens (a dev route, Expo Router `/__gallery`, or a `__DEV__` conditional in the root). Keep it importable, not auto-mounted.

## Manifest

Write `components/manifest.json` as an array of the manifest entries defined in `component-inventory.md`, in inventory order. The playground script uses it to know what to render.
